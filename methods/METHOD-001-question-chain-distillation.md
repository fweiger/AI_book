# METHOD-001 · 从多轮问题链提炼可复用的研究方法

- **状态**：CANDIDATE（设计已形成，尚未通过开平煤矿原对话实证提炼）
- **类别**：研究元方法 / 对话认知分析 / 跨路径成果沉淀
- **提出背景**：2026-11-01 用户与 AI 关于 AI_book 的明确需求讨论；用户要求从开平煤矿的既有研究对话中提取**自己的提问链、研究方法、经验与结论框架**，而不是重新研究历史或仅保存聊天。
- **待处理原案例**：[开平煤矿案例准入状态](../docs/intake/kaiping-coal-mine.md)
- **来源约束**：本卡记录从**当前可见需求对话**抽象的操作方法，不代表已读过此前分享的历史对话。真正的研究链及提问原句必须待原文到位后重建。

## 解决什么问题

已经开展过大量阅读或 AI 讨论，但产出散落在对话中。需要还原**问题如何演化、哪些推理操作推动了理解、哪些尝试产生经验、最终形成了哪些结论**，以便未来按问题类型寻找可执行的方法。

## 触发条件与输入
- **适用**：问题已讨论一轮或多轮，存在可回溯的用户问题、AI 回答、来源和最终结果；也可用于尚未完成的研究，但结论应标注未解决。
- **必要输入**：带顺序的原始对话/Issue 评论、来源链接及可用的完整性/覆盖标记；如涉及论据还需原始文献定位。
- **不能替代的输入**：仅有分享 URL、题目名称、AI 记忆摘要时，不可伪造提问序列、原文引句、成功经验及最终共识。

## 固定操作流程

1. **还原问题序列**：逐条抽取用户的实质问题，保留原句、时间/消息定位、所处讨论上下文；区分用户原问与 AI 主动生成的子问题。
2. **构建问题演化边**：将 Q_i 与 Q_j 关联，标注 `deepens`（深化）、`challenges`（质疑）、`reframes`（转换解释层级）、`branches`（分叉）、`resolves`（解决）或 `reopens`（重新开启）。每条边须说明为什么这样关联；相邻发言不自动构成逻辑因果。
3. **识别推理操作**：分别记录查来源、概念分解、时间顺序、反证、利益与制度约束、竞争假设、机制检验、类比/跨域迁移等**实际出现的**操作；不为了把框架填满而杜撰。
4. **恢复认知变化**：逐项比较“提问之前的候选观点 / 新信息或反驳 / 之后的认识 / 未解决的前提”，保留中间失败和回退。
5. **三类成果提炼**：a) Method：可重复执行的步骤+适用边界；b) Experience：某次真实尝试、结果、失败原因；c) Conclusion/Framework：具体命题、概念关系、系统解释与置信范围。没有某一类成果就保留空缺，不能强制填满。
6. **抽象与去重**：把特定事件名换成可泛化的问题机制，匹配已有 METHOD/FRAMEWORK；有重大差异才新建，类似方法优先追加实践记录/版本变更。
7. **反向追溯和验收**：每项方法卡指向至少一段可定位的真实研究过程；每项声称成功的经验需有检验标准和结果；每项最终结论标明资料级别和争议。缺少证据时降级为候选，不入“已验证”。
8. **回到下一个问题**：AI 收到新问题时同时检索领域知识和方法/经验；按匹配的研究机制及约束选用方法，并在本轮结束后反馈。

## 应输出的链路

```text
Source Conversation / Discussion
  → Question Q (原始提问 + 位置)
  → Reasoning Transition (为什么发生追问/转向)
  → Research Operation (实际采用的研究操作)
  → Evidence / Counterargument (已查与未查)
  → Insight / Claim / Framework (理解与结论)
  ↘ Method (抽象方法，含前提和边界)
  ↘ Experience (真实实践的成功、失败与修订)
```

## 质量与失败判据

- **可判通过**：能够从候选方法反向定位真实提问和推理转折，并据此说明方法何时可用、何时不可用；独立使用该方法时步骤明确。
- **不能声称**：方法“已经对开平煤矿验证成功”（目前未取得原始分享全文）；AI 一致同意即史实成立；只看关键词或末尾总结就推断整个研究路径。
- **失败模式**：只总结最后答案不总结问题演化；把史实时间线当思维方法；把同一史料的不同转述当独立证据；把未见原文的 AI 推断写成已确认的研究经验。
- **不适用**：无法取得任何讨论原文，或只有无法定位的摘要时，仅能建立“资料缺失/待提取”登记，不能产出案例特定的方法或知识链。

## 跨路径复用
- 单 AI 对话归档：直接提炼三类成果，不强制新增 Issue。
- GitHub 多 AI 协作：经讨论与证据复核后，提炼三类成果并通过 PR 版本化。
- 未来新增研究路径：共享同一输出协议，区别仅在输入和验证过程。
