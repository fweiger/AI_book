# TOPIC-012｜R2 在轨建设运营现金流模型：证据、算术与有效GPU小时（2026-11-14）

> 归属：[AI_book Issue #60](https://github.com/fweiger/AI_book/issues/60) · Draft PR #61。**研究状态：可复算的参数情景，绝非采购报价/可发射工程方案。** 已有R1质量模型，R2增加独立A（运输）、B（制造/运营/替换）和地面对照账本。所有组件制造价格、在轨年度运营成本、硬件寿命与故障率均为**特意设定的可调假设**；NVIDIA/NASA/BCG来源只约束部分技术或为外部比较。

## 一、为什么做这一轮

上一轮已反算首次入轨质量：100 kW约4.873吨，1 MW约48.73吨；运输敏感性可计算，但没有给出真正的B模块现金流。本轮基于该质量分项分拆太空设备制造、GPU、在轨组装、运营、计划性更新、部分故障、全模块损失应力测试和退役；同时独立建一个同功率地面设备账本。输出20年**未折现总成本**、**8%实质贴现现金流现值**、**贴现后的有效GPU小时成本**及**平价所需的临界运输美元/公斤**，三者严格区分。

## 三、1MW、运输费$100/kg时的逐年账本结果

单位：百万美元（M USD），所有成本为固定实质币值假设，**未折现**；GPU小时列为贴现后的单位服务成本。

| 方案 | A运输20年 | B建造运营20年 | 太空总额20年 | 轨道$/有效GPU小时 | 相对地面$/GPU小时 | 使每GPU小时平价的运输临界价$/kg |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 7.07 | 259.16 | 266.24 | 3.116 | 1.32× | -603.2 |
| lower_space_manufacturing | 7.07 | 233.50 | 240.57 | 2.655 | 1.12× | -172.1 |
| refresh_every_6_years | 6.57 | 229.16 | 235.74 | 2.740 | 1.16× | -272.8 |
| partial_failure_10pct | 7.87 | 307.16 | 315.04 | 3.546 | 1.50× | -937.1 |
| module_failure_1pct_stress | 8.05 | 275.60 | 283.64 | 3.269 | 1.38× | -683.7 |
| high_availability_low_manufacturing | 7.07 | 233.50 | 240.57 | 2.217 | 0.94× | 265.2 |

所有场景共同采用的地面20年未折现总额约 **$259.78M/MW**、贴现后每有效GPU小时约 **$2.365**，它是**本研究独立假设的地面模型**，不能混同BCG公布的$230–300M/MW区间。

**主要发现A：基准1MW在$100/kg时的轨道20年总额约$266.24M，但地面约$259.78M；将可用率/性能折减纳入分母后，轨道$3.116/有效GPU小时、地面$2.365。** 所以只看总额会低估轨道算力单位服务成本。

**主要发现B：降低空间硬件制造价格可以使轨道未折现总额低于地面，但仍未必实现单位服务平价。** 例如**lower_space_manufacturing**情景在$100/kg下为轨道$240.57M < 地面$259.78M，但轨道有效GPU小时的单位成本仍为$2.655 > 地面$2.365。

**主要发现C：如果同时假定轨道可用率提升到97%且性能折减消失（GPU有效输出与地面一致），叠加低制造成本情景，轨道GPU小时平价的**贴现运输阈值**约为$265/kg。** 这不是预计实际星舰运费，而是模型反算的必要条件之一；若运力/更新/发射频次无法支持，该条件仍不足以实现商业化。

**主要发现D：有些情景在“发射费为0”时仍无法平价。** 当**baseline**中轨道可用率90%、性能保持90%且设备定价维持假设，所需运价为负数（约-$603/kg）。这只意味着**在此参数组合下，不存在非负运输价格令每有效GPU小时平价**，不能解释为真实市场需要负运价。

## 四、方法与计算定义

- `GPU_count=floor(IT_kW*1000*GPU_TDP_power_fraction / 700W)`；1MW→1000张H200功率等效单元。**只计假设TDP分配，不是设备张数已认证。**
- 每年记录`A_transport`, `B_build_ops`, `ground_cashflow`, `orbital_effective_gpu_h`, `ground_effective_gpu_h`。A运输包括最初总质量、每4年IT更新载荷、每年2% IT故障的期望补发质量。B包括初始组件成本、IT制造与更新、年度运营和退役。
- 20年未折现成本是各年直接求和；贴现现值 `PV(C)=Σ_t C_t/(1+r)^t`；折现服务 `PV(H)=Σ_t H_t/(1+r)^t`。单位GPU小时成本 `PV(C)/PV(H)`，不能把PV成本除以未折现服务小时数。
- 目标平价交通价（可负）由 `(PV_ground / PV_ground_GPUhours * PV_orbit_GPUhours - PV_orbit_B) / PV_weighted_delivered_mass` 反算；负值代表当前输入下不能在非负运费区间达到平价。
- **整发专属发射**的`ceil(mass/capacity)×price`及离散发次还没有进入这版R2现金流；R1已有仅质量下界的研究。将它们视为**不同销售方式**，不得叠加。
- 全模块损毁应力场景是额外 `annual_whole_module_loss_probability×(A+B初始成本)` 的年期望费用，**没有构建严谨的离散续航/资产更新重置模型**，可能和预定硬件更新重叠；独立于BCG报告失效率口径。

## 五、代码真实执行/验收

- 使用Python 3.13标准库，在本轮工作环境执行： `python -m unittest -v test_lifecycle_cost_model.py` → **10/10 PASS**，其中第一版测试确实发生一次失败，原因是“低制造成本能自动实现GPU小时平价”的假设不成立。增加独立的“高可用率+低制造成本”测试情景后通过。
- 执行：`python lifecycle_cost_model.py --output results_lifecycle.json` → **60组情景输出**（2种规模×6组技术/经济假设×5组运输价）。
- 测试覆盖：年流量A/B账本和质量闭合、零运输成本保持B不变、平价阈值可反代、负阈值的不可行判定、折现现值、设备故障影响、更新周期影响、非法参数、网格数量、不同服务小时数。
- GitHub PR分支原模型V1代码与本机R1源代码有轻微代码差异，但调用的`calculate_design`输入输出一致；R2提交后需在仓库独立环境重新运行并记录结果，**尚未宣称CI或独立Agent验证完成**。
- 重大缺口：无真实空间级GPU集群采购价格、无GW级散热器可部署制造价格、无可靠太阳阵列可复用100W/kg×数百千瓦证据、无全模块失效率原始样本、无明确目标轨道/运力体积、无轨道长时任务真实GPU吞吐及星间网络带宽成本。

## 七、真正需要继续的唯一问题

以100kW/1MW为标准，**取得经公开合同或航天业可验证的零部件制造/在轨维护价格、实际GPU任务有效吞吐/寿命、真实目标轨道有效发射负载与规模制造能力**，用这些资料替换最重要的B类价格和可用率假设后，重新估计阈值。在缺少这些数据以前，不应针对美元个位数去无限优化模型精度，更不能宣布太空算力成本已超越地面。
