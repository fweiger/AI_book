## 为什么要分开三种东西

- **GitHub Issue #18**：讨论实际发生的地方。外部AI的每一轮回应都存留时间、身份、URL，可独立检查。
- **专题研究文档**：目前在 [Draft PR #17](https://github.com/fweiger/AI_book/pull/17) 的 `topic/TOPIC-004/2026-11-04-pearl-harbor` 分支；后续有证据后再经PR合并到 main。
- **原生 GitHub Discussions**：仓库已开启但创建类别、发布原生 Discussion 依赖 GitHub 页面或者受权的 GraphQL/CLI，可按 [迁移指南](DISCUSSIONS_HANDOFF.md) 创建。**当前不把Issue伪称成原生Discussion。**

## 长期可复用规则

1. **一个核心反事实只建立一个主辩论编号**，避免多AI在不同评论区重复且互不引用。下次新辩题使用 `DEBATE-002` 等。
2. 两位 AI 使用同一“已知资料集”，但在 R1 必须自行找到有独立出处的补充资料。主持人不能选择性只给某方有利材料。
3. R1 独立提交 → R2 交叉质询 → R3 修订与结论 → R4 正式中立裁决 → R5受限异议复核 → R6候选入库审查。主持人可记录 `INSUFFICIENT_EVIDENCE`，**不强制分出赢家**。
4. 证据等级 A 同期原始档案 / B 专业机构研究 / C 转引摘要或战后回忆 / D 假说。原始文献的**存在、已找到、已读到哪页**不能混写。
5. 历史人物/机构分别建档：陆军省、参谋本部、海军省、军令部、联合舰队、外务省。**正方不自动等于日本海军，反方不自动等于日本陆军。**
6. AI身份必须如实记录。未连入GitHub的模型只提交由用户**明确代贴**的 Markdown，不能冒称AI已独立发言或获得本仓库凭据。
7. 即使完成辩论，争议性说法也先进入讨论总结/PR，而不是自动改写为C-ID定论。正式入库需遵循仓库 [AGENTS.md](../../../AGENTS.md) 与 [版本协议](../../../VERSIONING.md)。
