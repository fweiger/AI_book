# TOPIC-018｜Lean 跨行业应用机会地图（首版）

> **版本：** v0.1 · 初始覆盖图  
> **使用方式：** 本图先按行业列出业务领域和候选问题，不对项目进行审计，不给出未经证实的商业排名。后续选定具体机会后，再补论文与 GitHub 项目映射。  
> **证据标签：** L-PROD = Lean 生产工作流；L-RESEARCH = Lean 研究/项目；L-POC = Lean 原型；FM-INDUSTRY = 一般形式化方法行业案例；HYPOTHESIS = 待验证机会。

## 1. 行业机会总览

| 行业 | 二级领域/业务环节 | 候选业务问题 | 可形式化对象/性质 | Lean 可能承担的角色 | 当前证据标签 |

| 软件、云计算与数字基础设施 | 云服务、权限系统、数据库、OS、API、数据解析、服务编排 | 授权决策是否符合策略；解析器是否安全；服务组件是否遵循接口；并发更新是否破坏不变量 | 规则语言、函数语义、状态机、数据格式、接口和不变量 | 可执行参考模型、定理证明、实现差分验证、关键程序精化 | L-PROD（Cedar）；L-RESEARCH（Aeneas/Veil 等） |

| 电信、通信与信息服务 | 网络协议、路由、编码、传输、消息系统、数据格式 | 协议是否满足安全/活性；编码解码是否互逆；消息时序是否满足约束；数据格式是否无歧义 | 协议状态机、代数编码、时间逻辑、解析器和数据契约 | 协议证明、信息论定理、可验证 parser/reference model | FM-INDUSTRY / L-RESEARCH（需逐方向核实） |

## 2. 重点行业的业务领域展开

### 2.1 数字技术与计算基础设施

- **芯片/硬件：** ISA 语义、硬件模块接口、微架构状态、指令级等价、编译器优化保持。
- **软件/云：** 权限策略、身份认证、API 契约、数据解析器、数据库事务、分布式服务状态。
- **安全/密码学：** 密码原语、协议安全、零知识证明、实现抽取、智能合约不变量。
- **关键问题：** Lean 是否进入设计规格、实现验证、证书检查或持续集成？哪些环节更适合模型检查/SMT？

### 2.2 金融与经济基础设施

- **银行与支付：** 账户状态、资金守恒、幂等支付、清算结算流程。
- **证券与交易：** 订单生命周期、撮合约束、撤单/改单状态、交易规则。
- **量化研究：** 数据可得时点、point-in-time universe、因子定义、组合约束、风险模型假设。
- **保险与精算：** 现金流、准备金模型、风险度量、合同规则。
- **经济学：** 均衡、拍卖、投票、机制设计、激励相容。
- **关键边界：** Lean 可以验证形式化规则与数学推导，但不替代市场数据真实性、统计检验、交易成本和样本外回测。

### 2.3 交通、工业与能源

- **交通：** 列控、飞控、车辆控制、交通信号、调度和故障降级。
- **工业：** PLC、机器人运动、产线联锁、工艺状态、设备协同。
- **能源：** 电网保护、调度约束、核能控制、安全监测。
- **关键边界：** 数学模型的证明必须与传感器、执行器、环境假设和实际控制实现建立明确连接；形式化模型不能自动证明物理系统安全。

### 2.4 医疗、生命科学与科研

- **医疗器械：** 控制逻辑、剂量/单位、报警状态和安全约束。
- **临床软件：** 规则引擎、工作流、权限、数据处理。
- **生命科学：** 生物过程模型、动力学、分子计算和统计模型。
- **科学计算：** 定理、单位、数值误差、求解器和模型内部一致性。
- **关键边界：** 形式化证明不等于临床有效性、实验真实性或生物模型对现实的充分描述。

### 2.5 AI、通信与公共规则

- **AI/ML：** 张量和算子语义、模型变换、受限模型的鲁棒性、控制器稳定性、AI 生成证明。
- **通信：** 协议、编码、传输和信息论性质。
- **政府/法律：** 规则、资格、合同、政策和审计流程。
- **关键边界：** 自然语言规则的形式化翻译本身需要领域专家审查；Lean 检查的是翻译后的命题，不负责自动判定法律解释是否正确。

## 3. 证据来源与解释边界

### Lean 专属案例入口

- [Lean 官方 Use Cases](https://lean-lang.org/use-cases/)：Cedar、Aeneas、ArkLib、Veil、Mathlib 等。
- [AWS Cedar 的 Lean 验证工作流](https://lean-lang.org/use-cases/cedar/)：生产 Rust 实现旁建立 Lean 可执行模型、证明性质并做差分测试。
- [ArkLib](https://github.com/Verified-zkEVM/ArkLib)：密码学证明系统方向的 Lean 研究项目。
- [Veil](https://github.com/verse-lab/veil)：分布式协议和 transition-system 验证方向。
- [Lean 社区项目目录](https://leanprover-community.github.io/lean_projects.html)：数学与科学项目发现入口。

### 一般形式化方法的行业证据

- [Formal Methods in Industry](https://doi.org/10.1145/3689374)：铁路、汽车、航空、操作系统、电商/云服务、硬件设计、光刻制造和移动设备等行业案例。
- [NASA 2025 Formal Methods at NASA](https://ntrs.nasa.gov/citations/20250006044)：软件、硬件、Web 服务、分布式数据库、交通、通信、核能、金融、医疗，以及 AI/ML、机器人和网络物理系统等方向。
- [DARPA Formal Methods Examples](https://www.darpa.mil/research/research-spotlights/formal-methods/examples)：parser、seL4、AADL 等案例及形式化方法的成本/收益边界。

**解释规则：** 上述一般形式化方法来源仅证明行业存在形式化验证需求或采用，不证明 Lean 被采用。每个行业的 Lean 专属证据必须另行建立。
