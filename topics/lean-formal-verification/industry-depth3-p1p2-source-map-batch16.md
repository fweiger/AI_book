## 二、最有实际价值的跨项目研究经验（不是新增实验）

- **把翻译正确性当作单独证明义务，而不是默认前提**：hax 0.4官方2026-09发布了Aeneas支持的Lean后端，信任文件明确Rust compiler、Charon、Aeneas、宏/core models及Lean kernel均是相关TCB；某个生成的Lean函数可编译并不保证与Rust源逐输入一致。ZisK的`root_soundness`源文件可见从raw RV64IM program和ROM绑定到Sail生成trace的条件性路径，并明确了layout/Sail decode/compiled image等外部边界；`Extraction/Dispatch.lean`宣称63 opcode dispatcher bridge，须与全部声称的端到端性质及作者trust ledger区别。
- **金融数学的可证性≠交易收益**：formal-mathfin的SDE Picard固定点、L2/Itô路径唯一性有具名Lean定理，彼此证明义务不同，文件注明更具体的积分表示与理论对照仍有细节桥接；既不证明行情数据PIT，也不证明现实价格路径满足Black–Scholes类分布或策略赚钱。
- **工业/网络/AI的抽象与实物不同**：KeYmaera X混合系统loop/dL是Scala证明器不是Lean；OpenPLC Runtime v3已EOL且源码研究改为继任v4的C扫描周期/优先级，版本交接必须明记；RDKit C++ SMILES解析/标准化与P4C C++ type checking/control-flow transforms是实现不是semantics-preserving proof。TorchLean type-indexed shape与Tensor Bool verifier定义有Lean源，但不能包含未覆盖的CUDA/FFI/NaN实现保证。
- **GPU和气象的负面证据必须突出**：Meta Lean Kernel Verify只对限定KIR role traces、TMEM ledger/barrier模型判定重用冲突，CuTe→KIR Python前端/unsupported instructions是TCB，不能等同GPU硬件/真实编译器保证；ClimaAtmos源文件`pressure_work_tendency!`在当前路径明确`nothing`，官方方程文档对部分能量耦合项明确`TODO: not yet implemented`；数值模拟成功不代表能量方程已经完整实现。这类可观察的模型—实现落差值得未来正式作为精化型研究课题，不转成本轮实现任务。
- **法律与教学不能混为Lean形式证明**：Catala法律默认演算、类型保持证明为F* `.fst`，并非Lean4；NNG4的自然数归纳关卡含Lean `Statement` 和教程参考proof，能说明教育交互结构，不能推出所有用户提交解法的系统soundness。原始论文、软件工程源码与教学作品要保留不同证据层级。
