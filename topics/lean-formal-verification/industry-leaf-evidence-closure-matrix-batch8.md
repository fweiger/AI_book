- **本轮是逐行证据分类，不是声称独立验证 83 个 GitHub 上游工程。** 来源级 `E1` 指已有对应 issue/论文/仓库/具体源码路径或作者文档的可回读映射；`NAMED_THEOREM_E1_NOT_BUILT` 表示名称/源文件可查，不等于 Lean kernel 运行、无 sorry/公理或全部假设已闭合。

- **条件与信任边界：** 锁定上游版本、模型假设、抽取器、axiom / sorry、外部 C++/CUDA/驱动、市场/临床/物理数据真实性、系统 refinement、形式化证明适用范围均可能是额外证据需求。无外部 clean build / 新证明运行；原始 Issue/Tracker 批准 Goal/AC 不变。

## 4. 关键陷阱与纠正

1. **分母**：83 个登记条目≠83 个终端叶节点；有 1 个 L3 是两个 L4 的父节点，所以终端叶节点为 **82**。同一 GitHub 仓库可关联多条数学性质，83 不是仓库数。
2. **SP1 / OpenVM / Zisk**：单个芯片行或 opcode 的条件性 soundness ≠ zkVM 全系统 correctness；Zisk 的 raw program binding、Aeneas lowering bridge、completeness 假设均应单列。
3. **Resonate / IFP / Veil**：Resonate 作者报告 31/92 无界证明、61 尚未完成；IFP 作者报告 93/103 invariant、10 尚待完成；Veil FloodSet 是同步 crash-fault 示例，不等于 BFT；trace-checker/model-checker 与无界 theorem 证据不互换。
4. **SciLean**：`odeSolve_fixed_dt := sorry_proof`，属于 OPEN_PROOF，不列入 kernel-verified 结果；其它 AD theorem 和 ODE 定义不能替此证明。
5. **LegalLean**：`TypeclassConstraint.lean` 中演示用显式 `axiom IsReasonable`；仅按定理和 import/依赖链具体结论，不将整个项目一概判为无公理或所有证明无效。
6. **金融 PIT**：已定位 `eligibleRows_no_lookahead` 但它没有证明股票池成分有效区间与 as-of 版本选择；后续实现、回测均仍属于 AI_Trader #488，不在本任务修改。
7. **TorchLean / GPU / 硬件**：Lean 的 exact arithmetic/IR 定理不等于浮点 CUDA/FFI/驱动和整机硅验证；Sparkle 的生成 SystemVerilog 与实现精化/物理时序另行成立。
8. **非 Lean 业务项目**：OCDS/Concerto、OpenAPS、ClimaCore 及其规则、测试和真实源码构成可用行业 reference，但不直接产生 Lean 形式化证明结论；明确记录 LEAN_GAP，避免隐形扩大成熟度。
9. **学术关系**：MathFin 的 RU 2000 是被形式化的经典风险理论，不是项目 companion paper；信息论库的 Zenodo DOI 是软件发行归档而非同行评审论文；StatsMLlib 是 AI4SLT 原仓库的后继整合线，不能按两个独立项目计数。
