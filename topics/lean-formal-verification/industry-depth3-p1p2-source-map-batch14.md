## 二、不能混为一类的证据

- **明确不可信的精化桥**：Lean-MLIR `PeepholeRefine.lean` 存在 `axiom refinement_correctness {p : Prop} : p` 与 `toPeepholeUNSOUND`。该精化路径有已知公理缺口，不能称编译后端已经受Lean证明。与另一个Hybrid Dialect定义节点严格分开。
- **有前提的形式化定理**：xv6iris顶层 adequacy 在作者源树可见，并使用`#print axioms`；前提包括gen0、power off、fs.img及给定轨迹。OpenVM SHA256 compression theorem不等于整个zkVM soundness或哈希抗碰撞。Markowitz两资产最小方差/N资产PSD、LeanInfoTheory的code rate与converse、Physlib量子熵/DPI均是**限定数学模型及具名定理源码**，不是本轮独立kernel审计/回测/设备安全。
- **非Lean行业项目依旧有价值**：SUMO C++微观仿真、pandapower Python潮流、Biopython FASTA/FASTQ、OCDS JSON Schema都是真实行业源码/标准，但没有发现与本条性质对应的Lean theorem，明确`LEAN_GAP`。OCDS`1.2-dev`分支的release schema内部ID仍标为v1.1.5，必须固定实际标准版本。
- **AI/教育工具不是证明**：LeanDojo-v2 Python前提数据库/训练入口为2023 LeanDojo论文的后继而非原版artifact；Lean Game Server 使用Lean环境检查玩家提交并呈现诊断，但源码作为服务器工具并不能直接作为独立的系统soundness定理。
