# 2026-11-23｜TOPIC-018 行业应用框架搭建

## 目标与决策

用户明确澄清 TOPIC-018 的研究顺序：当前不进入具体 GitHub 项目审计；首先建立 Lean 能够在哪些行业、哪些业务领域、哪些具体问题中应用的整体框架。框架完成后，再从行业/业务机会映射对应论文；由论文寻找对应 Lean GitHub 项目；只有当具体方向进入研究、复用或原型阶段时，才审计对应项目。

本轮不修改 AI_book #74 批准的 Goal、Scope、Non-goals 和 AC，只调整执行路径。项目审计从当前主线降为按方向触发的支撑工作。

## 本轮采用的框架结构

行业 → 二级业务领域/价值链环节 → 具体场景 → 业务问题/风险 → 可形式化对象 → 目标性质 → Lean 能力/适配边界 → 论文 → GitHub 项目 → 按需审计 → 原型/应用验证。

采用双轴组织：
- 纵轴：行业与业务场景。
- 横轴：跨行业问题类型与 Lean 形式化能力。

建立 12 个行业分类、12 类跨行业问题、Lean 能力映射、适配性判断、相邻技术比较、机会价值维度和证据成熟度标签。

## 主要依据

- Lean 官方 Use Cases：Lean 专属案例入口，包含 Cedar、Aeneas、ArkLib、Veil 和 Mathlib。
- Formal Methods in Industry（2024/2025）：一般形式化方法行业综述，覆盖铁路、汽车、航空、操作系统、云服务/电商、硬件、光刻制造和移动设备。
- NASA NTRS 2025：形式化方法应用领域覆盖软件、硬件、Web 服务、分布式数据库、交通、通信、核能、金融、医疗，并讨论 AI/ML、机器人和网络物理系统。
- DARPA Formal Methods Examples：形式化方法收益、成本、parser、seL4、AADL 等工程案例。

所有来源均区分 Lean 专属证据与一般形式化方法证据，不将后者冒充 Lean 行业采用。

## 验收检查

- 行业分类是否覆盖主要产业部门。
- 每个行业能否进一步拆到业务领域和具体问题。
- 是否明确可形式化对象和 Lean 的作用，而不是停留在行业名称。
- 是否区分 Lean 专属证据、一般形式化方法证据和潜在假设。
