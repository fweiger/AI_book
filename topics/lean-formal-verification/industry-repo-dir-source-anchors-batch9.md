## 2. 跨项目校验要点

1. **精确文件与特定定理不是同一证据：** 例如 VCVio 的 `by_hoare` 是 tactic macro 而非某个成功证明的安全定理；Resonate `state.lean` 是 abstract-machine 数据定义；ArkLib `Sumcheck/Source.lean` 是 Source 结构，不等于迁移中的 Interaction-tree IOR 安全结论。文件已定位并不使这些研究问题自动 LEAF_CLOSED。
2. **明确能够在源码看到 lemma/theorem 的案例：** Lean-MLIR `denote_rewritePeepholeAt`、VCVio `simulateQ_isMonadHom`、MathFin `binomialNoArb_crr` 与 `binomialPrice_call_tendsto_bs_closed`、StatsMLlib 四项、TorchLean `lowerToTapeChecked_eq` 和 CROWNQuery `acceptsText_sound`、SP1 Addw faithfulness、Resonate `invariant_along_trace`、ArkLib LiftContext 以及 Hachi honest opening。这些都是 **SOURCE_DECLARATION_READ**，未以本轮独立 Lean 4 kernel 编译与 #print axioms 验收为 PASS。
3. **版本与论文对应：** Lean-MLIR ITP24 和当前 main 分开；Brownian 项目/2025 论文直接 companion；StatsMLlib 是 ICML 2026 原 SLT 项目的后继整合库；VCVio 和 TorchLean 具体子模块对应论文的范围仍须逐条验证；MathFin CRR 具有参数假设而不等于真实市场定价精度；ArkLib current-status 与 ROADMAP 是项目一手技术资料而非独立学术审稿。
4. **核心依赖明确保留：** SP1 的 witness decode seam；Resonate 31/92、IFP 93/103（两者来自作者口径，不能当本次 CI）；TorchLean CROWN 精确证书 / IBP Float 检查的信任差异；Zisk production extraction 未闭合；所有 Lean 定理均不能自动证明真实数据、浮点实现或部署系统无错。
