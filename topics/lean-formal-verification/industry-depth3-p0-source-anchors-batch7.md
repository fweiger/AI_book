## 3. 纠正与信任边界（必须保留）

1. IFP 的 93/103 是项目 README 作者自报，不是本次独立 kernel 运行；完整 safety / epoch reconfiguration / liveness 是不同里程碑。项目中 `fv-veil-2.0` 包含 Veil 框架上游代码，**不能把通用 Veil 的验证案例计成 IFP 的专门定理**。具体 IFP 模型在 `IFPSafety` 目录。
2. SciLean 的自动微分 theorem 与 `odeSolve_fixed_dt := sorry_proof` 同库共存。必须按单性质而非仓库整体给出证明级别。
3. LegalLean 的作者“独立核验协议”宣称不含 sorry，但 TypeclassConstraint 明确以 `axiom IsReasonable` 展示人类裁量/类型限制：需要根据 import/依赖范围具体判定，而不是凭宣传材料给全库绝对无公理结论。
4. PIT 的 `eligibleRows_no_lookahead` 只关于观测可得性，股票池历史成分的时段/版本/追溯更正仍是未证明义务，不修改 AI_Trader #488。
5. Concerto 是业务 schema/数据序列化；OpenAPS 是健康控制业务代码；ClimaCore 是 PDE 数值计算库。三者即使有测试/发布/论文，也都不能充当 **Lean 形式化证明的已完成案例**。将真实业务问题与形式化需求分开映射，禁止项目统计混算。
