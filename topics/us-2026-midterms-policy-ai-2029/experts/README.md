# TOPIC-011｜专家 / 作品 / 观点三层库

**分工**：`experts.csv` 只登记发表者身份信息；`works.csv` 管视频、讲话、论文、访谈、报道与其发布时间；`../views/claim_register.csv` 把单件作品分解成若干可验证的主张。**一位专家有多部作品，一部作品有多条观点，多条观点可链接到同一H，反过来也成立**。

## 键与关联
- `expert_id`：EX001；不将「财经博主」自动标为学术权威，资质未核验就填UNKNOWN。专家与其被引用的官方机构是不同的主体。
- `work_id`：WORK001；含 `source_id=VIEW-S001`，与既有VIEW文件兼容，不修改已有VIEW-S001-Cxx。
- 观点 `view_claim_id` 为内容级 ID，见 [原观点登记表](../views/claim_register.csv)；归属 `WORK001` 通过 source_id 映射。
- [观点—假说交叉表](../hypotheses/view_hypothesis_links.csv)：每条 `VIEW-S001-Cxx` 可同时链接 H01/H09/H10 等；`CLAIMED_SUPPORTS` 表示评论者认为支持，**不表示证据真正支持**。
- 不同专家相同新闻源折叠成同一个原始证据族，与观点独立性分别管理；不同观点之间的分歧永远保留各自发布日期和可验证的截止日。

## 新增一位专家的最短工作流
1. 登记 `EXxxx`（身份与专业领域、资质核验状态），再登记 `WORKxxx`（作品及原始发布时间）。
2. 读取完整可访问原始材料，记录ASR文本/原文/二手摘要的深度；不能公开上传有版权的转写全文或非公开个人目录。
3. 一次拆分若干观点（原文中的事实指控、法律解释、机制推测、预测分别分行），绑定现有H或提出新H-ID候选。
4. 用独立文件/公告/数据做正反核验后，送入 [统一指标层](../metrics/README.md) 和 [链路研究](../chains/README.md)；同一条观点不能当验证其自己的独立证据。
5. 定期保留观点对照表，不能将「专家多数同意」解释为统计显著性或事实确定性。

最初的大湾区老姚视频由Ubuntu本地全量ASR读取（未回听原声）；仅保存作者原意的原创分析摘要。研究监测入口：[Issue #54](https://github.com/fweiger/AI_book/issues/54)。
