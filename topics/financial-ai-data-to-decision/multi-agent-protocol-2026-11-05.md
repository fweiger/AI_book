# TOPIC-006｜金融 AI 全行业多 Agent 研究协议 V0.1（2026-11-05）

> **研究目的**：系统回答“截至2026-11-05金融AI八条主线各走到了哪里？哪项能力已用于实际业务，哪项未被独立验证？如果要实现 Joseph Kim 对2027年的 P1/P2/P3 预测，还缺什么？”本文件是可交给不同 AI 的任务规范，**不表示已启动七个独立 AI 或完成七份报告**。

## 组织选择：1 主持 + 6 独立研究 + 1 独立红队

研究总范围见 [全行业地图](landscape-2026-11-05.md)。单 AI 可以做初轮证据搜集，但覆盖8条业务主线、跨监管/产品/论文/基准对照，推荐并行6个独立角色 + 1个独立红队。主持只协调、比对和更新台账，不将任意 AI 的总结当证据。

### R0 主持/编辑（协调，不单独裁定）
锁定研究期、统一八条主线、收集报告、审查原始 URL、去重、识别冲突、汇总共同证据表。无授权不要合并 PR 或修改正式 claims。首次报告截至 2026-11-05；新材料需要明确出现日期、发布日与版本。

### A 金融数据与检索专家（D01）
- 研究：许可金融数据与公开结构化数据、历史版本、财务实体/单位、as-of、RAG/MCP、来源审查；OpenAI / Claude / Bloomberg 数据架构对比。
- 核心争议：错误主要来自数据缺失、召回、证据定位、计算还是模型推理？分别测量，绝不以检索成功当作正确回答。
- 交付：数据质量维度表、提供商/接口索引、至少3个失败机制、评测指标（document/page/cell recall、源一致性）。
- 优先原始来源：OpenAI 官方、Anthropic 官方、Bloomberg 官方、SEC、PMLR 2026。

### B 投行研究与 Excel/财务建模专家（D02+D03）
- 研究：财报问答、三表、DCF/LBO、敏感性、估值、Pitchbook、审计和模型维护。
- 核心争议：文件生成≠财务正确≠模型可维护；区分 prompt、计算引擎、RAG、Skills、金融后训练。
- 交付：任务树、真实数据可得性、错因分类、MBABench/WorkstreamBench/Finance Agent 基准口径表。
- 严禁：凭空造财报、只展示截图便称完成专业估值。

### C 量化与前瞻性预测专家（D04；P3主责）
- 研究：LLM 文本信号、金融专用模型、收益/盈利/商品预测、风险控制及长期样本外检验；传统 ML/深度学习作为强基准。
- 核心争议：历史解释、EPS 预测和成本后交易收益是不同目标；反身性与 alpha 衰减能否使 P3 失效？
- 交付：FINSABER 与 OFR 研究对读，样本外/滚动切分/交易成本/多重检验框架，最强反例。
- 不允许：使用事后修订财报、偷渡未来新闻或编造 IC/Sharpe。

### D 银行风险、反欺诈、信贷与合规专家（D05）
- 研究：传统 ML vs GenAI/Agent，信用评分、风险监测、AML/KYC、支付欺诈、监管报告。
- 核心争议：哪些任务真的生产落地、哪些只是辅助决策，准确性/公平/审批责任的约束是什么？
- 交付：证据支持的部署类型、人工监督、误报/漏报与运营成本指标、治理法规清单。

### E 财富管理、保险与服务专家（D06）
- 研究：顾问辅助、客服、适当性、个性化建议、保险核保、理赔、保单处理。
- 核心争议：辅助生成/资料整理能否外推到直接提供建议或自主理赔？
- 交付：按业务链路的应用状态、可核查客户/流程效果和安全限制、反面案例。

### F 持续 Agent、治理与系统工程专家（D07+D08；P2主责）
- 研究：跨系统集成、任务持久化、故障恢复、幂等、权限、审计、数据隔离、成本，FSB 2026 12条治理实践。
- 核心争议：80%机构部署 Agent 是否可说明自主性? 参考 BoE/FCA 仅2%广泛自主权的调查结果。
- 交付：持续 Agent 系统条件、权限矩阵、审计与降级策略、长周期任务评分框架。

### G 独立红队/方法学裁判（不代表任何主线）
- 每项强结论至少检查：原始出处、日期、样本、是否厂商声明、实验定义、对立证据、可证伪点、跨基准不可比性。
- 必须提出不少于1个**对 P1/P2/P3 每项最有力的反对解释**；允许结论为“证据不足”。
- 不让一个 AI 把另一个 AI 的总结当作独立证据；不以多数表决下结论。

## 交叉流程：R0→R1→R2→R3→R4→R5

| 阶段 | 任务 | 进入下一阶段的门槛 |
|---|---|---|
| R0 证据与评测协议 | 确定8条业务主线、来源标准、基准不可比规则、最新时间点 | 同一评测口径、信息截面、审查规则公开 |
| R1 独立研究 | A-F 各自提交，不互相抄结论；至少原始来源 + 反证 | 每个主张有可访问原文和限制 |
| R2 同域交叉质询 | A核B的数据质量，B核C的建模，C核D/E的预测外推，F核各域自主权限 | 关键矛盾形成明确的 H / C 争议列表 |
| R3 独立红队 | G逐项审计、寻找反例、判断可证伪程度 | 争议标记 supported/conditional/unsupported |
| R4 实证验证 | 若公开数据/权限足够，在 AI_Trader 等适当实验环境做盲测；不存在条件就标阻断 | 报告数据版本、程序、完整结果与失败 |
| R5 知识沉淀 | 审核 Issue→Draft PR→正式知识节点/方法卡 | CI 结构通过 + 人工审查 + PR 合并方可 INTEGRATED |

## 评估矩阵：不能只问“模型有多聪明”
- **数据**：Coverage、staleness、point-in-time 正确率、revision 错漏率、来源证据精确率。
- **问答**：事实/单位/计算正确率、引用定位（文件→页→表→单元格）、拒答校准。
- **Excel**：数值/公式/结构/格式正确率、变更可维护性、整任务 all-pass、人工修复时长。
- **Agent**：多天任务完成率、故障恢复率、越权率、人工审批/接管成本。
- **预测**：EPS/价格任务的独立样本外损失与基准差异；若是交易，报告成本后回撤、风险、容量、多个市场状态。
- **经济价值**：审核及重做成本后节省的时间/费用；区分自报 ROI 与第三方核算。

## 最低证据准入与停止条件
- 监管/央行调查 = 自报采用，不等于性能保证；
- 厂商声明 = 产品发布或宣称，不能当作独立实验；
- 基准表现 = 特定测试的分数，需附版本与限制；
- 多 AI 结论一致 != 独立证据；
- 资料中出现未授权的私有/个人数据，停止公开上传；无法取得真实数据或使用许可时保留 NEEDS_EVIDENCE，不能捏造。

建议研究与演讲逻辑结合后的最终产物：**八主线证据地图 + 三项2027预测差距台账 + 财务建模任务基准 + 金融模型训练/工具消融方案 + 持久 Agent 可审计架构**。
