## 1. 目标与当前阻塞

入口：原始 ChatGPT 分享链接 https://chatgpt.com/share/6ae6c57b-cd0c-83ee-9efb-96ec53e324af 。

2026-11-01 本轮读取结果：分享页正文未返回，无法知道事件名称、时间跨度、人物或此前共识。因此当前阻塞是 **BLOCKED_ON_SOURCE_TEXT**。此处仅允许保存研究协议和检索入口，禁止伪造历史事件数据、替原对话编造问题或生成无来源时间线。

下一步来源准入：获取用户提供的对话导出/可读分享全文（可分段）；保留取得日期、原始链接、原文覆盖区间、导出格式和完整性检查；先人工检查公开仓库中是否存在隐私/版权风险，只保存可公开的研究性摘要和来源定位，不全文复制私人或受版权限制的材料。

## 2. 研究对象与稳定标识

- Topic：沿用 TOPIC-xxx，先查重后分配，不预先认定本试点是 TOPIC-005。
- Q-ID：topic 内问题，区分主问题、可执行子任务及开放讨论；Issue 为执行/讨论追踪，不替代 Q-ID。
- B-ID：沿用全局唯一书籍卡，避免重复注册；清实录可建书目/史料卡，记录版本、卷、页/数字定位。
- C-ID：topic 内可独立评价的研究命题；不得用 AI 共识替代证据。
- EV-ID：候选证据记录，带来源定位、权利状态、底本版本、时间和核验层级。
- EVENT-ID：独立事件记录；“发生时间”“成书/记载时间”“后人研究发表时间”分别存储。
- PERSON/PLACE-ID：仅在原始讨论及史料中明确出现时建立实体；历史异名保留别名及证据。
- METHOD-ID：跨专题可复用的方法卡，区别“研究结论”与“如何研究”。

上述新 ID 属方案建议；是否写入正式 knowledge-graph.json 需设计 schema 兼容迁移，不能默默更改旧 schema_version=1.0。

## 4. 严格的时间线与史料规则

1. 日期记录分层：原始年号纪年/干支/农历日，公历换算值、换算工具或版本、时区或日期精度（如仅至月份）；转换未核查则不得填“确定公历日期”。
2. 必须区分：历史事件发生日、史料声称发生日、奏折上奏日、档案收受日、实录编纂日、现代论文出版日，不能混成单一 timestamp。
3. 每个时间线节点至少指向 1 条已定位证据；多来源相互矛盾时保留并列版本，不以“多数来源一致”自动决断。
4. 《清实录》属于官修编年史料，可用于核实官方叙事、纪事位置，不等于全部因果关系已证实。引用时记录朝代、实录书名、卷次、原文日期、底本和原图/电子定位。
5. 因果边要求独立论证及竞争解释；“先后发生”不是“因果成立”。明确关系类型：记载、涉及、支持、反驳、转述、推断、类比、冲突、未验证。
6. 不凭模型参数、多个 AI 共识或重复引用的同一底本提升证据独立性；不得虚构原文、卷次、页码、档号。

## 6. 建议的 GitHub 工作方式

- Discussion：发表解释、疑点或反例；外部 AI 观点始终是不可信候选材料。
- Issue：可追踪的源材料请求、精读任务、史料核验、时间线冲突、因果检验；引用父/子 Issue 形成任务图。
- Topic 分支：形成研究产物，保持用户原有目录结构，书籍卡全局唯一。
- PR：附来源定位、被改变的 C-ID/EVENT-ID、验证命令及其运行输出；CI 检查只能证明结构合理，不能证明史料真实。
- 主分支：只有经审查 PR 合并后进入正式版本。审查不过时保持 open/draft 与明确阻塞原因。
- Agent 交接：保留 Issue/PR URL、分支 SHA、已访问/未访问原文、已形成/未形成结论、下一轮任务、可重复验证步骤。
